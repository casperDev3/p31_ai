# Project Overview: p31_ai

`p31_ai` is a specialized comparison playground designed for side-by-side evaluation of AI-assisted coding tools. It is not a unified application, but rather a collection of independent artifacts, each generated by a different AI tool (e.g., Claude, Gemini CLI, Cursor, Antigravity, Tour Agent Maker).

The primary goal is to preserve the unique "voice" and technical approach of each AI tool for educational and comparison purposes.

---

## Directory Structure

| Directory | Purpose | Build? |
|-----------|---------|--------|
| `pong-game/` | Angular 21 CLI app — a full Pong implementation using Signals. | **Yes** (`npm`) |
| `games/` | Standalone HTML/JS game variants (e.g., Doodle Jump). | No (Browser) |
| `landings/` | Standalone landing page HTML/CSS variants. | No (Browser) |
| `exp/` | Experimental one-off canvas or logic scripts. | No (Browser) |
| `memories/` | **Critical Documentation:** Detailed notes for each artifact. | N/A |

---

## Technical Context: `pong-game/`

This is the only directory with a full build pipeline.

- **Stack:** Angular 21.2, TypeScript 5.9, SCSS (global) / CSS (inline).
- **Architecture:** Standalone components, Signal-based state management, `@if` control flow.
- **Performance:** Game loop runs in `zone.runOutsideAngular`.
- **Testing:** No tests configured (`skipTests: true` is the default).

### Commands (Run from `pong-game/`)
```bash
npm install        # Initial setup
npm start          # Dev server -> http://localhost:4200
npm run build      # Production build -> dist/
npm run watch      # Dev watch build
```

## Core Mandates & Conventions

1.  **No Cross-Pollination:** Do **NOT** refactor one tool's variant to match another. The value of this repo lies in the differences between how tools solve the same problem.
2.  **Naming Convention:** New samples must follow: `<topic>_<tool>.html` (e.g., `pong_gemini-cli.html`).
3.  **Read Memories First:** Always read the corresponding file in `memories/` (e.g., `memories/pong-game.md`) before making non-trivial changes to an artifact.
4.  **Standalone First:** Keep HTML samples framework-free and self-contained. Only use framework patterns within the `pong-game/` directory.
5.  **Angular Style:** Within `pong-game/`, use 2-space indentation, single quotes, and prefer inline templates/styles for small components.

---

## Development Workflow

- **For Angular:** Follow the standard Plan -> Act -> Validate cycle. Validate via `npm run build` since no unit tests exist.
- **For HTML Artifacts:** Perform manual browser checks for layout and functionality.
- **Commits:** Use short, imperative messages (e.g., `feat: add x`, `fix: handle y`). Conventional Commits are preferred.
